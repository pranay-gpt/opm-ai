Turns on the Intelligent Timestepping algorithm.

The use of this keyword invokes an algorithm that works alongside the standard ECLIPSE timestepping algorithm to automatically adjust parameters in an effort to achieve more efficient timestepping for the simulators. It learns how to adjust the parameters by judging how well, or badly, the simulator is currently performing. It only attempts to change the timestepping in fully implicit runs but this doesn't include thermal runs in ECLIPSE 300. If the algorithm does not think it can improve on the default settings it will do nothing.

Specifically the algorithm does not affect the linear and non-linear convergence criteria or the minimum and maximum allowable timesteps.

The AITS keyword may not be suitable for "Reservoir Coupling" models (both master and slave reservoirs), because of the additional complexity involved in synchronizing multiple reservoirs.

Note: Whilst this algorithm does speed up the majority of cases it is not guaranteed to do so. There are cases where even the seemingly more sensible timestep choices of this algorithm actually lead to an increase in CPU time due to the non-linearity of the problem and the taking of a different path to the end of the simulation. The use of different timestepping can lead to different results. This is not the fault of the algorithm as such, but shows the sensitivity of the underlying problem to the timestepping taken.
