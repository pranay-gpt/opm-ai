This keyword can be used to multiply the connection transmissibility factors of selected well connections by a specified value. To multiply the transmissibility factors of all the connections in a well, leave items 3 to 7 defaulted. To multiply the transmissibility factors of a subset of connections in a well, you can identify the subset by their I,J,K location (items 3 to 5). A subset of connections can also be identified by their completion number (items 6 and 7). Completion numbers are set in keyword COMPLUMP.

The CPIFACT keyword is followed by any number of records, each containing the following items of data, and each terminated with a slash (/).

The set of records must end with a blank record, containing only a slash (/).

  1. Well name, well name template, well list, or well list template.

    A template enclosed in quotes can be used to refer to multiple wells or well lists. See Well name and well list template matching in the ECLIPSE Technical Description for further details. Well list names must be enclosed in quotes and begin with an asterisk (*). Well lists are constructed with the keyword WLIST.

  2. Multiplier to act on the well’s connection transmissibility factors and Kh values. This quantity can be a user-defined argument (UDA), and can be set with keywords UDQ and UDADIMS.

    The value must be greater than 1.0E-10.

    DEFAULT: 1.0

  3. I-location of one or more connecting grid blocks.

    DEFAULT: Negative (allows any I-location).

  4. J-location of one or more connecting grid blocks.

    DEFAULT: Negative (allows any J-location).

  5. K-location of one or more connecting grid blocks.

    DEFAULT: Negative (allows any K-location).

  6. Number of first completion in range.

    DEFAULT: Negative (allows any completion number up to item 7, if set).

  7. Number of last completion in range.

    DEFAULT: Negative (allows any completion number from item 6, if set).

If items 3 to 7 are all defaulted, the connection factor multiplier applies to all connections in the well.

If any of items 3 to 7 are set positive, the multiplying factor applies only to a subset of the connections in the well. The connections in the subset are those with I,J,K locations matching the specified location indices in items 3 to 5 and a completion number in the range specified by items 6 and 7. A zero or negative value for a location index (I, J, or K) matches any value of that location index. Similarly, a zero or negative value for a lower or upper end point for a completion range indicates that there is no lower or upper bound on the completion numbers.

Notes

  • When CPIFACT is read, the reference connection factors of the chosen set of connections are immediately multiplied by the specified factor to provide the connection factor used in calculations. If the COMPDAT keyword is subsequently used to reset any of their connection data, this causes both the reference connection factors and the currently applied factor from CPIFACT to be reset. If the multiplier is still required, CPIFACT must be entered again after COMPDAT.
  • CPIFACT is not cumulative—if it is used more than once on the same set of well connections, the multiplying factor is applied to the reference connection factors of the chosen set of connections each time the CPIFACT keyword is applied. The reference connection factor is the connection factor set using keywords other than CPIFACT.
  • Keywords WELPI and CPIFACT must not both be used on the same well at the same time without an intervening TIME, TSTEP, or DATES keyword.
  • The only difference between the CPIFACT and WPIMULT keywords is that CPIFACT is not cumulative. This allows item 2 to be set using a UDA to provide a varying but non-cumulative multiplier.
  • Only one UDA can be defined for each item per well at any one time. For any particular item, if two UDAs are defined for different connections on the same well, then the corresponding value will be calculated for all UDA-controlled connections using the most recently requested UDA.
Note: This keyword can be used with OPTIONS3 (item 43) to avoid an error message being generated when a local grid well is referred to.

Example

CPIFACT
 PROD1  1.3  /(all connections in the well PROD1 )
 PROD2  CU_PIF 1* 1* 5 /(all connections of well PROD2 in layer 5 have their reference connection factor multiplied by the current value of the CU_PIF UDQ at each timestep)
 PROD3  0.6  1* 1* 1* 7 7 / (all connections of PROD3 in completion number 7)
