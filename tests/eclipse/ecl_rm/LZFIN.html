The LZFIN keyword can be used to generate a logarithmic assignment of the number of LGR cells between the host global grid cells, and logarithmic sizing of the LGR cells within each global grid host cell, in the z-direction. The keyword should be placed after the keyword CARFIN introducing the local grid, and before the local grid data is terminated with ENDFIN.

The keyword should be followed by some or all of the following items, which define the central cell (fracture) thickness in the z-direction and the method used to calculate relative cell sizes for LGR cells in each global host cell. The data record should be terminated by a slash (/).

  1. Central cell thickness.

    UNITS: m (METRIC), ft (FIELD), cm (LAB), m (PVT-M)

    DEFAULT: 1.0 (all unit sets)

  2. Option controlling relative sizes of LGR cells within each global host cell.
    LINEAR The LGR cell sizes are calculated to increase logarithmically, with the scale factor determined by the central cell thickness and the number of LGR cells in the central global host cell.
    UNIFORM The LGR cell sizes are the same within each global host cell, with the exception of the central LGR cell which has thickness determined by item 1.

    DEFAULT: LINEAR

LZFIN can only be used in local grids with an odd number of cells in the z-direction. In addition, the algorithm requires that the central global host cell contains at least three LGR cells and all other global host cells contain at least one LGR cell. The minimum number of LGR cells in the z-direction is therefore K2-K1+3. In order to generate an LGR which doesn't have outer cells where global host cells contain only one LGR cell in the z-direction, it is 2*(K2-K1)+3.

If it is possible to generate a grid where no global grid host cell only contains one LGR cell (i.e. at least 2*(K2-K1)+3), this is done. If it is not possible, the same algorithm is used but with the number of LGR cells in the outer global host cells set to 1.

In ECLIPSE, it is not possible to have an LGR cell which overlaps a boundary between global grid cells. The algorithm for assigning the number of LGR cells in each global grid host cell is therefore an integer algorithm and, especially for small numbers of LGR cells per host cell, it may not produce smoothly increasing LGR cell sizes. The relative sizes of the global grid host cells is not considered in determining how many LGR cells each will contain.

To determine the logarithmic growth factor, the specified central cell thickness is compared with DZ for the central global host cell. This factor is then used for the entire LGR. The global grid geometry must therefore be defined before a local grid using LZFIN is specified.

LZFIN does not apply to radial refinements introduced with RADFIN, and cannot be used in a nested LGR, an LGR which spans an even number of global grid cells in the z-direction, or in the same LGR as either NZFIN or HZFIN.

ECLIPSE will output its internally calculated values for equivalent NZFIN and HZFIN keywords in the PRT file. To make minor adjustments to the cell sizes, edit the values and use the modified keywords to replace LZFIN in the data file.

Local grid refinement is described in "Local grid refinement and coarsening" in the ECLIPSE Technical Description.

Example

CARFIN
-- NAME   I1 I2  J1 J2 K1 K2 NX NY NZ
   LGR2   3  4   1  2  5  7  2  2  15 /
--Three global cells in z-direction to become 15 local cells
--Eclipse will determine how many are in each of the three global cells
--Cell sizes will increase logarithmically within each global cell
LZFIN
 1.5 LINEAR /
