Note: This keyword is for use only with the Petrel Reservoir Geomechanics module and you must not add it to ECLIPSE datasets. The information about the keyword is for reference only.

The workflow is described in the "Geomechanics" section of the ECLIPSE Technical Description. In this workflow, the Petrel Reservoir Geomechanics module couples the VISAGE and ECLIPSE simulators, using the ECLIPSE fluid simulation results to compute the geomechanical response of the reservoir to changes in pressure, fluid saturations/composition and temperature. These calculations are performed at particular report steps in the simulation called coupled timesteps.

The Petrel Reservoir Geomechanics module activates the workflow by adding the VISAGE keyword to the RUNSPEC section. It uses the VISOPTS keyword to control the interaction with ECLIPSE.

The data consists of some or all of the following items. The data must be terminated by a slash (/).

  1. Whether this is a workflow initialization run.
    YES GRID, INIT and initial restart data are output, and the run is switched to NOSIM with the report steps that would be performed written to the EDESC communication file.
    NO Output of GRID, INIT and initial restart data is not required, and only coupled timesteps are written to the VDESC communication file.

    DEFAULT: NO

  2. Whether the run is to exit at the next coupled timestep encountered.
    YES Exit the simulation when the next coupled timestep is encountered.
    NO Continue the simulation when the next coupled timestep is encountered.

    DEFAULT: NO

  3. Whether the dynamic coupled timestep mechanism is active.
    YES If the field pressure has changed by more than the relative tolerance in item 4 since the last coupled timestep, then the next report step will be treated as a coupled timestep.
    NO There are no dynamic coupled timesteps.

    DEFAULT: NO

  4. The relative tolerance on the field pressure for a dynamic coupled timestep. This must not be a negative value.

    When the change in field pressure since the previous coupled timestep (or since the beginning of the simulation if there have been no coupled timesteps) divided by the pressure at the previous coupled timestep (or initial pressure if there have been no coupled timesteps) exceeds this tolerance, a dynamic coupled timestep will be triggered as long as item 3 of this keyword is set to ‘ YES ’.

    DEFAULT: 0.05

  5. Not used in this release
  6. Whether the existing restart frequency is to be maintained.
    YES If there are RPTRST requests to reduce the frequency of the restart files, then these should be honored in the current run.
    NO The workflow default restart frequency (RPTRST argument BASIC=2) should be used.

    DEFAULT: NO

  7. Whether the existing restart content is to be maintained.
    YES If there are additional RPTRST contents over and above those required for the workflow (mnemonics BASIC=2 and ROCKC), then these should be honored in the current run.
    NO Only the content required for the workflow should be output to the restart files.

    DEFAULT: NO

  8. Whether it is an error or a warning to not re-specify well connections (which are required in order to recompute well connection factors after a change of permeability) before the first timestep when performing a restart.
    ERROR (or E) It is an error, and no simulation will be performed.
    WARN (or W) It is a warning, and simulation will proceed using the well connection factors from the restart file.

    DEFAULT: ERROR

Example

The example below is not a workflow initialization run and it will stop when it next encounters a coupled timestep. It has the dynamic coupled timestep mechanism active and it will treat a report step as a coupled timestep if the relative change in the field pressure since the last coupled timestep is greater than 0.1 (that is 10%). Any inputs specified by the Petrel Reservoir Geomechanics module for restart frequency and content will be honored in this run. If well connections have not been re-specified before the first timestep, it will produce an error.
