Functions available for quantity definitions

The following functions are available for use in quantity definitions. Without brackets, the functions are evaluated in order of decreasing precedence, with binary functions of equal precedence evaluated left to right and unary functions of equal precedence evaluated right to left. Brackets can be used to reorder the evaluation as required.

Binary functions take two arguments, one from the left and one from the right. Note, the majority of binary functions operate on the intersection of the two UDQ sets, that is the output is only defined if both corresponding input elements are defined. A smaller number of the binary functions operate on the union of the two UDQ sets, that is the output is defined if either of the corresponding input elements are defined. The binary functions are elemental, operating on each element in turn. As a consequence both the left and right functions need either to be of the same type, for example, a well UDQ set, or one of the arguments needs to be a scalar. If one argument is a UDQ set and the other a scalar, the scalar value is applied to all elements in the UDQ set.

Unary functions take a single argument usually supplied in a following bracket. The Unary functions are either elemental, or return a scalar value. The majority of the unary functions only operate on defined elements although a few also operate on undefined elements.

User-defined quantity definitions are evaluated as real numbers constrained to lie in the range specified by item 2 of the UDQPARAM keyword. Values exceeding this range will be limited and ECLIPSE will issue a message notifying you of this. Similarly, should an argument fall outside the domain of a function then the element will be returned undefined and the user notified.

Note: When combining connection vectors ending in L, i.e. lumped completion vectors, it is important to realise that the summary vector for each connection in a lumped completion contains the same lumped completion value. Unary scalar operations such as SUM and PROD can therefore combine the same value multiple times into the result, if they act on every connection in a well.
If item 5 of the UDQPARAM keyword is set to WELL then enhanced interaction of well and connection UDQ sets is enabled.
  • the unary scalar operations will act on connection sets to produce well sets rather than field scalars.
  • the binary operations (both intersection and union) can be used to combine a well set and a connection set, with the well set value for each connection's well being used in place of an explicit connection set value. The result is a connection set.
  • a well set can be used in place of a connection set, with the well set value for each connection's well being used in place of an explicit connection set value.

Because of the ambiguous nature of some specifications (e.g. DEFINE WUTEST SUM(CUTEST)), which could be intended to use either a well UDQ set or a single scalar value for all wells, it is not possible to have some definitions produce well sets and others field scalars.

Note: Since functions can be nested, it is possible to generate field scalars from connection sets even when WELL is specified. For instance, SUM(SUM(CUTEST)) when WELL is specified is equivalent to SUM(CUTEST) when WELL is not specified.
