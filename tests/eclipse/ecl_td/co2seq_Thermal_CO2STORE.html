Thermal CO2STORE

The CO2STORE option can be used with the THERMAL option for live oil and gas. The fluid properties are defined similarly to a standard thermal case, but the CO2 component is allowed to dissolve in the aqueous phase. When using the CO2STORE option together with THERMAL it is assumed that the temperature range of the reservoir is limited to 12-250 °C in a model with additional hydrocarbons. For models with no additional hydrocarbons, the range is 1-250 °C.

If no oil K-values are supplied the phases assumed is as for a standard CO2STORE case, a aqueous water rich phase and a CO2 rich gas phase. The density of the CO2 rich phase and the water vapor is computed as for the standard CO2STORE option. Additional components are taken as water components unless you supply water K-values for these components or define them as gas only components. This is done by the keywords KWTABTn and CVTYPE. Note that the CO2 and H2O component is allowed to be defaulted when using the CO2STORE option. If this is done the usual computations for the solubilities of CO2 and H2O will be applied.

Additional oil/gas components can be made non-soluble in water by defaulting them in the KWTABTn keyword. Their viscosities can be defined in the GASVISCT and OILVISCT keywords, and if the viscosities of CO2 and H2O are defaulted, the usual computations for their viscosities will be applied.

In THERMAL it is possible to define the H2O components as part of the components defined in CNAMES, or if left out it will be added as the last component of the system. If the H2O component is specified it is also possible for H2O to be in the oil phase. However this is only allowed if oil K-values are supplied using KVTABTn, where you need to supply the split of H2O between oil and vapor.

Note: With thermal CO2STORE, the aqueous mole fractions are named AMF, while XMF refers to the oil phase mole fractions.
Note: If the only explicitly supplied component is CO2, the CNAMES keyword is not required.
Density and viscosity
The density of the aqueous phase is computed as described by the keyword DENAQA, equation 432.1) and VISCAQA, equation 432.3. Default values will be assigned for CO2/CH4, NACL/CACL2/CACO3 component. The vapor phase density is computed as for a standard thermal case, but the CO2 and H2O contribution to the phase specific volume is computed internally.

Similarly for vapor phase viscosity the CO2 and H2O contribution when calculating the phase viscosity are computed internally unless a component specific value for the viscosity is assigned.

Enthalpy
The aqueous enthalpy is computed by the parameters given in the keywords SPECHW1 and SPECHW2.

For the gas phase the usual parameters given for a thermal live oil run should be supplied, note that for CO2 the parameters defining the enthalpies for both an oil and a vapor should be given even if not an oil phase is considered.

The H2O molar enthalpy in the vapor phase is computed internally.

An alternative enthalpy formulation for all phases is available for systems with CO2 and H2O without additional hydrocarbon, which takes the CO2 enthalpy from internal tables generated with the Symmetry* process software platform. These tables contain enthalpy as a function of pressure, temperature, and (optionally) CO2 molar fraction of the phase, up to a pressure of 600 bar and a temperature of 250°C. Within the table, values are linearly interpolated. Above these values, extrapolation is linear for pressure and constant for temperature.

This option is controlled using the CO2ENTH keyword. When it is activated, the SPECHx, HEATVAPx and ZFACT1 keywords are not required. Zero enthalpy is taken to be the enthalpy of the liquid phase at the temperature and pressure specified in the STCOND keyword.

Relative permeability
The relative permeability needs to be of the three phase type. If an oil phase is not considered, the oil relative permeability needs to be assigned dummy values.
Note: WSF and GSF cannot be used to specify the relative permeabilities.
Low temperature option
The Spycher-Pruess ( Spycher and Pruess (2005) and Spycher and Pruess (2009) ) method is normally limited to a temperature range of 12-250 °C. For systems with CO2 and H2O without additional hydrocarbon, lower temperatures are allowed and calculations are based on a linear extrapolation of CO2 and H2O k-values from 12 °C downward to 1 °C. At these low temperatures, both component k-values are approximately linear with temperature. This option can be disabled by setting item 438 of the OPTIONS3 keyword to 1.
Detection of hydrate formation
An additional CO2STORE option exists to detect the formation of CO2/H2O hydrates at low temperatures. It is only applicable to systems with CO2 and H2O without additional hydrocarbon. Several salts can be modeled using the CO2STORE option. These have the effect of depressing temperatures at which hydrates can form in this fluid system or, in other words, are hydrate inhibitors. A hydrate formation envelope was fitted as a function of pressure and salt concentration from predictions with the Multiflash hydrate calculator ( Infochem, 2019 ). The effect of all salts is modeled using an equivalent set of NaCl ions in solution. The accuracy of these envelope predictions is ± 2 ° and the accuracy of the fit is ±1.2 °. Two methods are available to report hydrate formation:
  • A summary vector can be defined that reports hydrate formation in grid blocks using the summary keyword BHYD (or LBHYD for local grid blocks).
  • A 3D array can be requested where a value of 1 indicates hydrate formation, invoked with the HYDRATE mnemonic in the RPTRST or RPTSCHED keyword.
Initializing the study
The typical conditions is that the reservoir is water. It is possible to assign the initial aqueous mole fractions by the AMFVD keyword when using the EQUIL keyword. If the reservoir is initialized by enumeration the aqua mole fractions are assigned by the AMF keyword.
Compatibility
The thermal CO2STORE option is currently not compatible with the multisegment well option.
